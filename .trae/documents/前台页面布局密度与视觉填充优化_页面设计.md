# 页面设计文档：布局密度诊断与填充方案（Desktop-first）

## 0. 全局设计约束（新增模块必须遵守）
### Layout
- 桌面端：以 `container + max-width` 为主体（建议 max-w-6xl），模块间距默认 24px；避免 `space-y-12` 贯穿全页导致“空洞感”。
- 列表页：使用 CSS Grid（4 列为主），当数据不足时用“信息卡/导购卡”补齐视觉节奏。

### Meta Information（统一建议）
- Title：`助听器商城 - {页面名}`
- Description：一句话说明本页目的（例如：首页=选购入口；推荐=个性化选品；结算=提交订单）。
- Open Graph：`og:title/og:description/og:type=website`，商品详情可补 `og:image`。

### Global Styles（与现有实现保持一致）
- 颜色令牌：使用 `--c-bg/--c-surface/--c-text/--c-muted/--c-border/--c-primary/--c-on-primary`。
- 可访问性：
  - 命中区 ≥ 48px（使用 `.a11y-hit`）。
  - 焦点：仅用 `:focus-visible`，outline 3px（使用 `--focus-ring`）。
  - 高对比模式：继承 `html.hc` 的变量覆盖；新增模块不得写死灰度色。
  - 动效：尊重 `prefers-reduced-motion`；新增动画需可被该媒体查询禁用。

## 1. 首页（/）
### Page Structure
- 结构：纵向分段（Hero → 分类 → 商品网格 → 填充区 → Footer）。
- 现状“空洞点”：Hero 高度固定 400px + 全局 `space-y-12` 导致首屏后留白；商品不足时网格断层。

### Sections & Components
1) Hero Banner（保留，收敛留白）
- 桌面端将内容容器 padding 从 `px-12` 调整为响应式（`px-6 lg:px-12`），Hero 高度可改为 `min-h-[320px] lg:min-h-[400px]`。
- 按钮：保持 `.a11y-hit`，aria-label 已具备；增加 `aria-describedby` 指向一句“会进入个性化推荐”。

2) 分类条（密度增强）
- 分类按钮在桌面端补充“当前筛选摘要”（如：全部/耳背式 + 关键字），用轻量 badge（border-2 + var 颜色）。

3) 商品网格（稳态布局）
- Grid：`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-6` 保留。
- 当商品数 < 8：在网格尾部追加 2~4 张“导购卡”（仍指向 /recommendations 或当前分类筛选），避免大面积空白。
- 骨架屏容器加 `aria-busy="true"`，加载完成移除。

4) 填充区（新增，核心）
- 采用 3 列卡片（桌面端）/1 列（移动端）：
  - 卡1：选购指南（入口到推荐页）
  - 卡2：服务保障（售后/配送/无障碍承诺）
  - 卡3：适配场景（会议/看电视/户外等 tags，点击后跳推荐页并预填场景）
- 每张卡：
  - 标题（h3）+ 2 行说明 + 主按钮
  - 整卡可点击但必须保证键盘可达：用 `<button type="button">` 或 `<a>`，避免 div click。

## 2. 商品详情（/product/:id）
### Page Structure
- 现状“空洞点”：信息区仅“描述+分类+库存+数量”，当描述短时右侧显空；且存在与全局变量不一致的灰色体系。

### Sections & Components
1) 顶部：标题区 + 返回
- 建议增加面包屑（首页 / 分类 / 商品）提升信息密度与定位感。

2) 主信息双栏
- 左：图片（保留 aspect-square）。
- 右：名称/价格/库存/购买组件（保留）。
- 风格一致性：将 `text-gray-*` 与 `border-gray-*` 迁移到 `text-[var(--c-*)]` / `border-[var(--c-border)]`。

3) 信息补强（新增）
- 卖点列表：3~5 条 bullet（如：降噪、续航、适配等级等），如无真实字段则用“通用卖点文案 + 不夸大”。
- 保障/售后：折叠面板（Element Plus Collapse），默认折叠，减少噪音但填充空洞。
- 相关推荐：4 卡横排（复用 /api/product/list 按 category 过滤）。
- 无障碍：折叠面板标题为 button，支持 Enter/Space；图片区 alt=商品名。

## 3. 购物车（/cart）
### Page Structure
- 现状“空洞点”：表格下方仅一行合计；桌面端右侧大面积留白。

### Sections & Components
1) 非空态：左右布局（桌面端）
- 左：商品表格（现有 el-table）。
- 右：结算摘要卡（新增）：合计、运费/优惠说明（文案即可）、“去结算”主按钮。

2) 凑单/推荐（新增）
- 在摘要卡下方或表格下方展示 4 个商品卡（同类/推荐），减少“结束得太突然”的断层。

3) 空态（保留）
- 增加一行“你也可以去个性化推荐试试”，并提供次按钮链接。

## 4. 结算（/checkout）
### Page Structure
- 现状“空洞点”：商品表仅显示 product_id/quantity，信息不足且不利于确认；地址仅一个 textarea。

### Sections & Components
1) 步骤提示（新增）
- 顶部增加 Step Bar（Element Plus Steps）：结算 → 支付 → 完成（完成页可暂不新增，仅做视觉提示）。

2) 商品确认表（优化）
- 列：名称、单价、数量、小计；ID 作为 tooltip 或折叠列。

3) 地址区（优化）
- 默认：多行地址输入（保留）。
- 若用户已有地址：提供下拉选择“默认地址/最近使用”，选择后自动填充输入框（不新增页面）。

4) 支付方式（补强）
- 提供单选（微信/支付宝）与提示文案；提交按钮旁显示“提交即代表同意服务条款”。

## 5. 个性化推荐（/recommendations）
### Page Structure
- 左侧画像表单（sticky）+ 右侧结果列表（保留）。

### 填充与密度增强
- 顶部“筛选摘要 chips”：展示听损等级/预算/场景/品牌，便于用户理解当前配置。
- 空态：给出 2~3 个示例配置按钮（点一下即可填充并刷新推荐），减少空白。
- 读屏：结果更新使用 aria-live（现有 liveText 已做）；新增 chips 需是静态文本或可删除按钮（有 aria-label）。

## 6. 登录/注册（/login, /register）
### Page Structure
- 桌面端两栏：左表单、右信息卡（新增）。

### 右侧信息卡（新增）
- 模块：隐私说明、无障碍功能提示（大字/高对比/字幕/语音）、“登录后可进行的操作”。
- 要求：不抢主流程注意力（弱层级），但填充视觉空洞。

## 7. 个人中心（/profile）
### Page Structure
- 顶部信息卡 + Tabs（保留）。

### 填充与密度增强（新增）
- 顶部信息卡下新增“概览卡片行”：
  - 待支付订单数、售后处理中数、默认地址标签
  - 数据来源：现有 orders/addresses 列表聚合即可。
- 快捷入口：按钮到“推荐/购物车/地址”，统一 `.a11y-hit`。

## 8. 无障碍验收要点（针对新增模块）
- 键盘：Tab 顺序符合视觉阅读顺序；所有点击区可 Enter/Space；无键盘陷阱（Drawer/Dialog 关闭可 Esc）。
- 视觉：对比度在普通与高对比模式下都清晰；focus-visible 不被阴影/边框覆盖。
- 读屏：状态变化（推荐更新、加购成功、表单错误）用 aria-live 或组件自带 role=alert。
- 动效：prefers-reduced-motion 下无强制动画；骨架屏不造成阅读干扰。
